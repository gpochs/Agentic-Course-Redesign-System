# Review the reusable system separately

1. Start only after a valid production declaration, matching handoff approval
   and independent verification, accepted current-lineage HITL 3, and a
   persisted mandatory system-review offer whose current-run status is
   `requested`. A stale, missing or mixed-lineage receipt fails closed.
2. Read root `AGENTS.md` and use the `course-redesign-system` skill.
3. Compare actual run evidence with workflow skills and umbrella routing;
   plugin or platform adapter; `AGENTS.md`, rules, workflows, agent
   configurations and role reference; project template, state schema and
   migration; validators, tests and QA; documentation; memory or other
   workflow-owned durable instructions; schedule contracts; permissions,
   tools, egress and automatic behaviour; and compatibility, benefits,
   regressions, risks, residual risks and rollback.
4. Produce a versioned proposal with exact targets, benefits, regressions,
   compatibility, tests, residual risks, and rollback. Keep course content,
   answer keys, personal data, and copyrighted assets out of reusable files.
5. The request authorises only read-only review and one versioned proposal. It
   does not authorise system-file changes, installation, publication/release,
   runtime activation, schedule registration/modification, an immediate run,
   or added MCP, connector, authentication, permission or external egress.
   Do not edit before a separate matching System Gate. If files are approved,
   create only an inactive candidate and validate it in a disposable folder.
6. Stop after validation evidence and choices are presented. Do not activate,
   install globally, register a schedule, or trigger a run.
