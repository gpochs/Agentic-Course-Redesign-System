# Show the lecturer the draft

Use this guide when the redesign calls for an editable file, cloud document, LMS activity, website or other digital tool. The lecturer can begin from a description and choose a format later. Ask what learners need to **do** with the result. A worksheet that needs handwriting space, a spreadsheet that needs to recalculate, and a quiz that needs to withhold feedback require different review methods.

## When the lecturer authorises copies only

Before each write, verify the object in the editor against the approved copy's stable ID, course or folder, and visibility. A duplicate title, the owning course's new ID or the tab opened previously cannot establish the identity of a linked item. Use the lecturer's naming convention if they supplied one.

Check the editable dependencies separately. A copied LMS page might still point to the original quiz bank. A copied chatbot might still use the original knowledge base. Confirm each resource to be modified is a separately approved copy, then verify the link resolves to that copy. A read-only reference can stay in place only within approved access. If the editor opens an original or the link target cannot be verified, hold that write, continue unrelated work and offer to author a local draft or request approval for the specific copy and relink. After saving, reopen the parent and repeat the learner route to verify the intended copy and audience.

## Choose the review surface

Use the orchestrator as the lecturer's single point of contact. A specialist can identify a source, build an approved working copy or test a draft. Send its preview and observations through the orchestrator. Give only one agent control of the same tab, document or application at a time.

- For a public research source, open the relevant passage in the visible in-app browser when web research is in scope and the lecturer wants browser review. Give the finding and link it supports. Opening every search result makes the important evidence harder to find.
- For an LMS or cloud editor, invite the lecturer to open the exact course, folder or document in the in-app browser, sign in themselves when needed, and select the tab to use. Reuse a selected tab and existing access. If browser access is unavailable, explain the available host control in one sentence and offer to continue from a description or an authorised export. Check the selected account, course or workspace, document, and current role before acting.
- For local files, use the lecturer's selected working folder. Show the editable file alongside a browser-compatible PDF, HTML or image preview when one is supported, useful and within the approved targets. Label the displayed version. For a file type the browser cannot faithfully display, open the native editor if available or provide a local openable link. A static preview lets the lecturer judge layout. Verify formulas, editing, narration or branching in the application that runs them.
- When a connector, installed skill or specific app would enable a requested action, name the capability it adds and let the lecturer decide whether to use it. If unavailable, continue with an approved editable draft, an importable file, or a worked example in chat. Explain which later action still needs that tool. A preview must keep the original audience and handling conditions. Prefer a private local preview over uploading a file to a new viewer.

## Author a private LMS or cloud draft

1. Identify the exact destination and action at the existing Gate 3 blueprint review. An approved local working-copy target may bind a specific private external draft using the record described below. Include the LMS or cloud service in the agreed processing environment and data boundary. Source inspection still follows the applicable eligibility and source-access decisions. An approval to read another course, a link preview, or a local export does not authorise changes in the LMS.
2. Confirm the platform's draft/visibility controls and who can see a newly created object, including inherited folder permissions and notifications. If saving would make content immediately visible beyond the approved audience, produce the approved local draft and explain the available publishing options. Use the host's current UI or official documentation for that installation. An LMS name alone does not identify its version, extensions or edit rights.
3. Open the named private draft or create the one agreed object below the named parent. Record the resulting object ID or stable link and revision if the service exposes them. After a timeout, refresh and match the ID/parent/title before retrying. Stop to resolve conflicting edits or ambiguous duplicates. Never create a second item as a blind retry.
4. Reopen the saved revision. Use the least privileged available preview, distinguish the editor view from a simulated learner view, and identify actions the preview cannot exercise. Test with fictional input in the approved sandbox. Keep grades, bank keys, personal records and teacher-only settings out of learner previews.
5. Show the saved draft in the selected browser at the named artefact gate. Ask a focused pedagogical question about the actual change, for example “Would a learner know what counts as evidence in the second prompt?” Apply authorised revisions to that same draft, reopen it and show what changed. Carry the lecturer's decision into the handoff and HITL 3. Publishing, enrolling, notifying, changing access or writing to a gradebook each needs its own explicit scope.

**Gate 3 record for a private external draft.** Use a `working_copy` target under `04_Working_Copies/` for its local review record. Attach `external_draft` only when the lecturer wants live authoring. Record the service's HTTPS `origin` (host and optional port), exact `container_id` (course/folder and parent node as applicable), `draft_name`, `action` (`create_draft` or `edit_draft`), and `visibility` (`restricted_draft`). For editing an existing private draft also supply its stable `object_id`. For creation omit that field and capture the assigned ID in the local review record after saving. Show this destination in plain language with the local filename. Copy the approved bindings, keyed by local relative path, into `approval_receipt.external_draft_targets` when recording the Gate 3 reply. Keep credentials and signed URLs out of records. On resume compare the approved binding with the service's current location and visibility. A local target by itself grants only a local write.

At the named artefact gate, include the reopened draft's stable `external_object_id` in its acceptance record. On platforms offering both an editor preview and an edit-mode switch, check the result after leaving edit mode. Record exactly which view you observed.

## What to test in the selected format

| Material | Test before showing it as ready |
| --- | --- |
| Word, Google Docs, handouts, PDFs | Reopen the editable master. Inspect semantic headings, links, reading order, table headers and space for responses. Render all pages for a paginated deliverable. Check clipping, page breaks and text extraction. Where accessible PDF delivery is required, inspect tags and reading order in the exported PDF. |
| PowerPoint and Google Slides | Inspect every slide at presentation size, then check editing, object reading order, alt text, notes, captions or animations as applicable. Show the actual slide the lecturer needs to judge. Scrub skipped slides and speaker notes from learner copies when these contain restricted material. Google documents its slide reading order and availability of skipped slides in shared files. [Google Slides screen-reader guide](https://support.google.com/docs/answer/1634140?hl=en) |
| Excel and Google Sheets | In an editable copy, enter fictional inputs, independently calculate an expected result, test a blank or boundary value and recalculate. Show the relevant range, formula and result. Check units, headers, validation, charts, protections and hidden sheets. Print layout matters when printing is a deliverable. For Office files use the available accessibility checker alongside manual inspection. [Microsoft 365 accessibility guide](https://learn.microsoft.com/en-us/microsoft-365-apps/deploy/accessibility-guide) · [Google Docs Editors accessibility guide](https://support.google.com/docs/answer/6199477?hl=en) |
| LMS pages, modules and quizzes | Check sequence, instructions, resources, visibility and prerequisites. In a quiz verify scoring, partial credit where used, feedback timing, attempts and the distinction between instructor keys and learner feedback. Test correct, incorrect and unanswered paths where the sandbox permits. Confirm the specific importer, supported version and item types before choosing an interchange format. Moodle XML is Moodle-specific. QTI versions differ. A successful XML parse establishes syntax only. [Moodle XML format](https://docs.moodle.org/501/en/XML) · [1EdTech QTI versions](https://www.1edtech.org/standards/qti/versions) |
| OLAT/OpenOlat | Consult the actual installation. In UZH's traditional course preview, unpublished changes can be visible and several learner actions, including starting tests, are unavailable. Check the draft in the course editor or the applicable preview, and record any learner action still untested. On leaving the editor choose the option consistent with the agreed publication scope. [University of Zurich OLAT editor guide](https://docs.olat.uzh.ch/de/manual_user/learningresources/Using_additional_Course_Editor_Tools/) |
| Websites, forms, interactive software, media and other tools | Try the intended learner task end to end, including one error and recovery where applicable. Check keyboard focus/order, labels, narrow viewport, zoom, media captions/transcript and completion feedback. For software, identify the installed version, editable project and supported preview/export. For interactive media, play a representative input/branch and verify its feedback. W3C's preliminary checks can flag barriers and cannot establish full conformance. [W3C accessibility review](https://www.w3.org/WAI/test-evaluate/preliminary/) |

At handoff, identify the editable item or local path, review view and audience, revision, checks actually performed, concrete results and unresolved limitations. For example, “I reopened the private draft and checked the learner instructions. The course preview disables submissions, so submission and grading still need a sandbox attempt.” Use the lecturer's existing revision, conditional acceptance and acceptance choices.
