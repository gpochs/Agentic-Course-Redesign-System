# Review a course in Codex desktop

**Choose models.** Codex custom agent TOML files support `model` and `model_reasoning_effort`. A configured role value takes precedence over an explicit spawn value, then agent defaults, then the parent's setting. Check the actual loaded profile and the spawn tool available in this session. The distributed profiles leave the model unset. Use an authorised per-call override only if the offered tool supports it (some hosts require a fresh, bounded context). Inherited permissions and provider still apply. A running parent cannot switch itself mid-turn: offer the teacher the app or CLI model picker for the next turn. If the host cannot verify the child model, label it unverified or keep the role in the current session when capable. [OpenAI subagent configuration](https://learn.chatgpt.com/docs/agent-configuration/subagents)

**Choose sources.** Once the teacher has selected the source types and approved their use, take only the named files or folder and the exact course tab they share. Use the app’s Files and folders picker or supplied file links for local inputs. A teacher may select a course tab and a handout together. Use the attached tab if available. For a fresh session the teacher can open the course in the built-in Browser (`@Browser`) and sign in there. If a second site opens for a quiz, check the separate scope before accessing it. Continue from the in-scope tab, an approved export or the description. [OpenAI browser guide](https://learn.chatgpt.com/docs/browser?surface=app)

**Show the change.** Open the saved working copy in the desktop file preview when the host offers it. When the enabled host exposes `open_in_codex`, request the approved file by its exact path. A `queued` result records a pending preview. Verify that the viewer rendered the item before reporting it open. Go to the exact handout page or learning-outcomes slide, identify the previous and revised wording, and leave the file open beside the conversation. If control of the file viewer is unavailable, provide the clickable editable file and the page or slide number. For PDF tags, slide builds, formulas or other app-specific behaviour, open the compatible installed viewer or editor if its use is in scope. A local file link alone records which file was offered. [OpenAI file preview guide](https://learn.chatgpt.com/docs/artifacts-viewer)

**Try the learner’s task.** In the selected private LMS, open the learner preview and check its role indicator. For a safe practice quiz, tab to the options, choose a fictional response and check where focus lands and when feedback appears. If it would submit to a real course, keep the attempt private and leave grading unverified. Use browser annotations when available to identify the exact spot the teacher wants to revise. Reopen the saved version at the same location and read back the result.

**Keep the checks specific.** For keyboard or screen-reader access, inspect the task in a suitable accessibility view or authorised assistive technology. Name what you tested and which checks are still open. If the desktop panel cannot render the file or inspect the learner view, use an approved accessible local preview, an installed viewer, or a teacher-led check. Keep the observed, teacher-reported and unverified results distinct. The CLI has no visual file preview. A compatible IDE viewer or a local file link can support a teacher-led review there.

**Use optional skills at the point of need.** Check the tools exposed in this session first. A Documents, Presentations or PDF capability can help with a requested edit or export when available. Tell the teacher which material and destination it would use and offer the existing local route. Any new installation, connection, disclosure or publication is a separate decision. End the preview with the teacher’s decision for this version.
