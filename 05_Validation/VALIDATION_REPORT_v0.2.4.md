## Interaction-only change verified

One unresolved consequential question remains in view at a time. A native card
is used only when the live host tool contract can present the complete valid
option set plus a custom-answer path. When that capacity is unknown,
unavailable or exceeded, the same single ordinary-chat question lists every
valid numbered option plus `Other - type your answer`, then waits.

The system never prunes, hides or combines valid choices merely to fit a card.
Long sets may use adaptive dependency-based clusters only when choices share
evidence or constrain one another; every valid option remains visible and the
lecturer may split, merge, reorder or rename the grouping. Custom answers are
preserved verbatim before their canonical interpretation is confirmed. Only a
safest truthful, evidence-aligned, reversible choice may be labelled
`Recommended`, and it is never preselected.

Eligibility categories and outcomes, substantive option sets, course
semantics, specialist authority, gate order and meanings, approval tokens,
state schema 8 and lifecycle transitions are unchanged.
