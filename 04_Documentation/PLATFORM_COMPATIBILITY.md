# Platform compatibility

All editions use the same six skills and the same lecturer decisions. Host capabilities determine which models can be selected, whether a choice card is available, and which files or browser tabs can be opened. Choose the installed, subscription-backed model in the host. Each specialist receives a bounded brief. If the host runs only a single agent, identify sequential role reviews as such.

| Host | Where to use the edition | What the lecturer can inspect |
| --- | --- | --- |
| ChatGPT web | Directory plugin in Chat or Work where the account offers it. | An uploaded working copy, approved connection or browser available in that session. |
| Codex desktop | Directory plugin, repository marketplace or project skills. | Open the selected learner file in the file preview or use Browser for its private activity. Inspect a slide animation in the presentation app. A teacher can use the copy-ready review packet when desktop control is unavailable. [File preview](https://learn.chatgpt.com/docs/artifacts-viewer) · [Browser](https://learn.chatgpt.com/docs/browser?surface=app) |
| GitHub Copilot | Native plugin or project skills in a project Session. | Files and Changes show the selected draft and tracked wording. Browser or a compatible Canvas can show it beside chat. A teacher may use Computer Use for an approved receiving app. Check the active model in the picker, since Copilot offers several model families. [Desktop panels](https://github.blog/ai-and-ml/github-copilot/github-copilot-app-for-beginners-using-the-diff-terminal-and-browser/) · [Computer Use](https://docs.github.com/en/copilot/how-tos/github-copilot-app/computer-use) · [Models](https://docs.github.com/en/copilot/reference/ai-models/supported-models) |
| Claude Code | Claude Desktop’s Code tab or a terminal, using the native plugin. | The local desktop Browser pane opens HTML and PDF links. Changes supports line comments. An existing signed-in Chrome tab requires a separately approved connection. The terminal can link the exact draft for the teacher to open. [Claude Desktop](https://code.claude.com/docs/en/desktop#preview-your-app) |
| Google Antigravity | Plugin at project or account level. | Documents and Artifacts in the Overview panel can reopen a PDF or walkthrough. A Browser tab can show a private learner activity. Whether the agent can operate that tab depends on the account and surface. [Side panel](https://antigravity.google/docs/side-panel) · [Browser](https://antigravity.google/docs/browser) · [Model picker](https://antigravity.google/docs/models) |
| OpenCode | Project or account skills and agents. | Files, Review and the built-in desktop browser support checking a draft alongside the conversation. ### Model selection during the redesign

Choose task matching, a single model, or a decision at each step. In task matching, the teacher approves named tasks, models, account routes and usable fallbacks once. Use a fixed model for a single-model run. Preserve the specialists’ read-only tool restrictions when assigning them. If a host silently substitutes a model, record the observed model or mark its identity unverified.

| Edition | Main conversation | Individual specialist |
| --- | --- | --- |
| Codex desktop | Use the session’s model and effort picker. | Use only model and effort overrides offered by the live subagent interface or approved profile. A fork of the full conversation may require inheritance. If an explicit override needs a fresh context, pass only the bounded role brief. [OpenAI subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents) |
| GitHub Copilot | Choose a model and supported effort in the Session dropdowns. | Where available, the CLI task tool accepts per-call model and effort. Profiles can prefer or require models. Auto can select the same model for all roles, and a displayed parent model alone leaves the specialist model unverified. [App sessions](https://docs.github.com/en/copilot/how-tos/github-copilot-app/agent-sessions) · [CLI agent settings](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference) |
| Claude Code | Use the picker or `/model`. | The Agent tool can take a family alias and supported effort for one call. Profile definitions may use an exact model ID or inherit. Policies can force or substitute a model. The interactive `/tasks` list can show the resulting model and effort. [Claude subagents](https://code.claude.com/docs/en/sub-agents#choose-a-model) |
| Antigravity | Use the picker or `--model` at a turn boundary. The account determines the available thinking levels. | Built-in custom-role model tiers are `inherit`, `flash` and `pro`. The edition inherits the selected parent. A teacher can switch the parent for a role when an exact per-call choice is unavailable. [Models](https://antigravity.google/docs/models) · [Custom roles](https://antigravity.google/docs/subagents) |
| OpenCode | Use `/models` or a CLI model ID with its supported variant. | Profiles support `provider/model#variant`. The supplied roles inherit the parent. The documented subagent call names a role, description and prompt. Change the parent at the boundary or use an already approved suitable profile. [Agents](https://opencode.ai/docs/agents#model) · [Subagent tool](https://opencode.ai/docs/tools/#subagent) |

For the optional second opinion after Step 9, show the teacher progress through all nine steps, including skips. An agent's activity log alone cannot tell you which teaching decision the lecturer made. Compare the family of the model that produced the materials with the reviewer’s actual model. Use current evidence of suitability and the teacher’s included account options. Present the exact selected materials and receiving app, account and model for the teacher’s final decision. Each host supports a manual handover of the approved packet.

**Skills, plugins and hooks.** The packaged skills guide the review when invoked. A separately reviewed hook could run a local format or link check on an approved draft in a host that supports that event. Hooks execute code or commands and may see tool data. This workflow leaves them unconfigured and runs the teacher’s optional review on request. GitHub documents hooks for particular agent surfaces. OpenCode exposes server and GUI plugins with different extension points. Check the active host before proposing a specific integration. [OpenAI hooks](https://learn.chatgpt.com/docs/hooks) · [GitHub hooks](https://docs.github.com/en/copilot/concepts/customizations/hooks) · [Claude Code hooks](https://code.claude.com/docs/en/hooks) · [Antigravity hooks](https://antigravity.google/docs/hooks) · [OpenCode plugins](https://opencode.ai/docs/build/plugins/)

In the tested Codex Plan mode, `request_user_input` supports two or three explicit choices and an automatic Other field. Other modes may expose a different question control. Use the ordinary-chat fallback if the live control cannot show the full decision.

If the host can show every option and accept a custom answer, use its choice card. Ask open questions in ordinary conversation. If a card would hide an option, list the complete set in chat. A model, browser tool, connector or user-wide installation supplies a capability. The lecturer chooses which sources and actions to authorise for each course.
